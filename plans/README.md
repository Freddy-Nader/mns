## What goes in the CMS

The rule is that what changes over time goes in the CMS, and design and fixed copy stay in code, where Freddy keeps changing them.

| In the CMS (Mauricio edits) | Stays in code (Freddy edits) |
|---|---|
| Dates, including masterclasses and courses | Interface copy in `lib/dictionaries/` |
| Scores and their link to a recording | Biography (`content/bio.ts`) |
| Videos, synced from YouTube, plus pin, hide and order | Contact details and channels (`content/site.ts`) |
| Programmes | Lesson offers and their copy |
| Press quotes | Poster colours (`tono`), layout, tokens, images |
| Store and channel numbers, featured programme | The course link (a bit.ly he controls himself) |

The CMS is Sanity (decided 2026-11-17, open to change later). Every Sanity-specific line lives in `studio/` and `lib/cms/`, so a swap means rewriting those two folders and nothing else.

## Findings considered and rejected

- **Keystatic**: no release since December 2025 and an open report of a blank admin on Next 16 with Turbopack. Revisit only if Sanity is dropped.
- **Vercel Cron for the video sync**: the Hobby plan runs crons once a day, but issue #5 asked for a short delay, so the sync runs every 12 hours. GitHub Actions is used instead.
- **YouTube Data API**: needs a key. The long-form RSS feed (`UULF` playlist) is enough for the latest uploads and excludes Shorts.
- **Embedding the Studio at `/studio` in the Next app**: it would add Sanity's bundle to the site build for no gain over the hosted `*.sanity.studio`.
- **Storing social drafts or raw media in Sanity**: the free plan's dataset is public.
- **A full nine-category code audit**: not requested this run. Only the CMS and the open issues were planned.
